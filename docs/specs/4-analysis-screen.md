# #4 分析画面：URL を入れるとグラフが出て、クリックした時刻から再生できる

## 目的

配信のアーカイブを見返す人が、URL を入れるだけでコメント数の30秒ごとのグラフと動画を見て、盛り上がった時刻から再生できるようにする。見た目は [分析画面](../screens/analysis.md)（案 A）と [トップ](../screens/top.md)（案 B）に従う。取得・集計は #3 の API とワーカーを使う。

## 使う人と最初の画面

[分析画面](../screens/analysis.md) の表のとおり。375px でスクロールせずに、ヘッダー・タイトルと情報・動画の枠・グラフの上の部分が見える。

## 受け入れ条件

### 入口（トップ → 分析画面）
- トップで YouTube の URL を入れて「分析」を押すと、`POST /api/jobs` でジョブを作り、`/analysis/<ジョブID>` へ移る。
- 入力の形が違う（`invalid_url`／`unsupported_url`）とき、入力欄の下に ⚠ と理由を出し、ボタンは押せない（トップの状態の表）。Twitch は「まだ対応していません」と出す。
- 送信中はボタンを読み込み中の表示にして、押し直せない。API の失敗（通信エラー・5xx）は右上のお知らせで知らせ、入力した URL は残す。
- 同じ動画が既にあるとき（`done`／`running`／`queued`）は、既存のジョブの分析画面へ移る。

### 分析の状態
- `/analysis/<ID>` は、ジョブの状態を `GET /api/jobs/:id` で確かめる。`queued`／`running` の間は「分析中」を出し、3秒ごとに確かめ直す。`done` になったら自動でグラフと動画に切り替わる（再読み込み不要）。
- `done` のとき、タイトル・コメント数（`result.totalComments`）・グラフ・動画を出す。
- `failed` のとき、`error.message` を画面に出す（理由コード別の文言は #3 のとおり）。「別の URL で分析し直す」ための入口（PC は URL 入力欄、スマホはトップへ戻る入口）を残す。
- 存在しない ID・形が違う ID は「分析が見つかりません」とトップへ戻る入口を出す。
- 状態確認が一時的に失敗しても、直前の表示を残して確かめ直す。連続で失敗したときは右上のお知らせで知らせる。
- 分析中・読み込み中は、動画・グラフの枠を薄い面の仮の形で出し、枠の位置は変えない。

### グラフ
- コメント数のグラフは、`chat_buckets`（30秒ごと）の各区間を1本の棒で出す。棒は `--chart-1`、いちばん多い区間だけ `--accent`（同数が複数あるときは最初の1つ）。
- 長い配信で棒が潰れないよう、棒の数が多いときは区間をまとめる（まとめた棒のコメント数は合計）。まとめても、押した棒の開始時刻は正しい。
- 棒または時刻を押す（キーボードは Tab で棒に移って Enter／Space）と、プレイヤーがその区間の開始時刻へ移って再生する。押した棒は選択中として見た目で分かる。
- 動画が画面に見えていないスマホでは、押したあと動画の枠までスクロールして再生する。
- 棒にマウスを乗せる（または押す）と、時刻（`h:mm:ss`）とコメント数が出る。
- コメントが0件のとき、グラフの枠に「コメントがありません」と補足の文字を出す（動画は再生できる）。
- 棒の時刻と高さを読み上げ用の名前に持つ（色だけに頼らない）。

### プレイヤー
- YouTube の埋め込みプレイヤー（IFrame Player API）を使う。動画 ID は `result.videoId`。
- 棒を押したとき、プレイヤーの準備ができていればその時刻へ移して再生する。準備前に押されたら、準備ができた時点でその時刻から再生する（押した操作を捨てない）。
- プレイヤーの読み込みに失敗した（広告ブロック・通信エラー・埋め込み禁止）とき、枠の中に理由と「YouTube で開く」リンク（その時刻つき）を出す。グラフは使える。

### 画面の配置
- 375px・1024px・1440px で崩れず、横スクロールが出ない。見た目が細い棒でも、押せる範囲は 44px 以上に広げる。
- PC（1440px）は、上に URL 入力欄、その下に タイトル・コメント数・動画・グラフ。スマホは1列で タイトルと情報、動画、グラフ（[分析画面](../screens/analysis.md) の配置）。
- ヘッダーは共通部品にし、トップと分析画面で使い回す。

## 範囲外

- チャット一覧と絞り込み（#5）。右の細い列は #5 で足すので、今回は左の列だけを出し、PC でも幅は動画とグラフに合わせて中央に寄せる。
- 配信元（チャンネル名）・配信の長さの保存（取得ジョブの `result` に無いため、長さはプレイヤーから取れたときだけ出し、取れなければ出さない）。
- 最近の分析の一覧（トップ。保存の仕組みが #8 以降のため、今回は出さない）。
- ログイン・利用制限（#7 以降）、Twitch（#6）、ジョブの再実行ボタン。
- DB スキーマの変更（しない）。

## 仮定

1. 開発中はログインなしで使える（Issue の仮定どおり）。
2. グラフ用のデータを返す API が #3 に無いので、`GET /api/jobs/:id/buckets`（`[{ startSec, count }]` を `startSec` 昇順で返す。`done` 以外は 409）を足す。既存テーブルを読むだけで、スキーマは変えない。
3. グラフは外部のグラフ用ライブラリを入れず、SVG／HTML で自作する（新しい依存を増やさない・リスク基準 8 を避ける）。
4. プレイヤーは YouTube の IFrame Player API をスクリプトで読み込む（YouTube 自体が既に取得対象で、新しい有料サービスではない）。
5. 状態の確認は、サーバー送信イベントではなく3秒ごとのポーリングにする（単純で、ジョブが数分のため）。
6. 「配信元」と固定の「長さ」は DB に無いので今回は出さない。表示は「タイトル・コメント数」と、取れたときの長さ。
7. トップの URL 入力は、#2 で形が決まっているものの配線だけを行う。見た目の新しい方向性は足さない。
8. リスクは `risk:medium`（新しい画面と読み取り API。DB 変更・認証・外部送信なし）。
