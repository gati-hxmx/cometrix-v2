# #50 古い分析の掃除と、データのバックアップ・戻し方

## 目的

コメントの表（`chat_messages`）は増え続けるので、長く開かれていない分析のコメント本文を消して重くならないようにする。あわせて、DB が壊れても戻せるように、Postgres のバックアップを取るスクリプトと戻す手順を用意する。運用する人（オーナー）向けで、見た目の新しい画面は作らない。

## 使う人と最初の画面

新しい画面なし。既存の [分析画面](../screens/analysis.md) は、掃除済みの分析を開いたときに小さなお知らせを出すだけ（375px でスクロールせずに見える位置、基本 8-1 のお知らせの形）。

## 受け入れ条件

### 開いた日時の記録
- `jobs` に `last_opened_at`（null 可。null のときは `created_at` を開いた日時とみなす）と `messages_purged_at`（null 可）を足す（マイグレーション。既存の行は変えない）。
- `GET /api/jobs/:id` が `done` のジョブを返すとき、`last_opened_at` が1時間以上前（または null）なら現在時刻に更新する。1時間以内なら書き込まない。`done` 以外・存在しない ID では更新しない。
- 同じ API は `messagesPurged`（真偽）を返す。

### 掃除
- 関数 `purgeStale(db, { days })`（`src/lib/purge.ts`）。`status = 'done'` で、`messages_purged_at` が null、かつ `coalesce(last_opened_at, created_at)` が `days` 日より前のジョブについて、`chat_messages` の行を削除し `messages_purged_at` を現在時刻にする。1ジョブごとの1トランザクションで行い、途中で失敗しても他のジョブは続ける。
- 消すのは `chat_messages` だけ。`jobs`・`chat_buckets`（30秒ごとの集計）・`result` は残す。
- `days` は既定 90。環境変数 `PURGE_AFTER_DAYS` で変えられる。1未満・整数でない値のときは掃除せず、エラーをログに出す（誤って全部消さないため）。
- `running`・`queued`・`failed` のジョブには触らない。
- 境界：ちょうど `days` 日前のジョブは消さない（`days` 日を超えたものだけ）。
- ワーカーが1日1回（起動直後を含む）掃除を呼び、消した件数をログに出す。
- 掃除済みのジョブのコメント API（`/messages`）は 200 で空配列を返す。集計 API（`/buckets`）は今までどおり返る。

### 画面
- `messagesPurged` が真の分析を開くと、チャット一覧の場所に「古いため、コメントの本文は整理しました。コメント数のグラフは見られます。」と出す。笑い・絞り込みの操作は出さない。

### バックアップと戻し方
- `scripts/db-backup`：`docker compose exec db pg_dump`（カスタム形式 `-Fc`）で `backups/cometrix-<日時>.dump` を作る。`backups/` は git に入れない。保存先は第1引数で変えられる。失敗したら 0 以外で終わり、空のファイルを残さない。
- `scripts/db-restore <ファイル>`：指定のダンプを、上書きしてよいか確かめたうえで（`--yes` で確認を省略）DB に戻す。
- `docs/backup.md`：取り方・戻し方・定期実行の例（cron）・保管の注意（ダンプにはコメントが入るので外に公開しない）。
- ローカルで「データを入れる→バックアップ→DB を消す→戻す→件数が一致」を実際に試し、結果を PR に貼る。

## 範囲外

- 掃除済みの分析の再取得（「もう一度取得」ボタン）。必要なら別 Issue。
- バックアップの自動アップロード（外部ストレージ）、暗号化、世代管理。
- `jobs` 行そのものの削除、失敗ジョブの掃除。

## 仮定

- 「開かれていない」は「`GET /api/jobs/:id` が呼ばれていない」で判断する（分析画面を開くと呼ばれる）。ログイン機能がまだなく、閲覧者は区別しない。
- 集計（`chat_buckets`）は小さい（30秒ごと）ので残す。グラフはずっと見られる。
- 90 日は仮の値で、環境変数で変えられる。
- 開いた日時の更新は1時間に1回までにして、閲覧のたびの書き込みを避ける。
- 消したコメントは元に戻さない（バックアップから戻す以外）。再取得は範囲外。
- リスクは high：スキーマ変更とデータの一括削除に当たるため、マージは人が承認する。
