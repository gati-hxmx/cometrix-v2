# #53 好きな言葉・スタンプの数をグラフに重ねる

## 目的

アーカイブを見返す人が、「笑い」以外にも自分で決めた言葉・スタンプ（YouTube のスタンプ、Twitch のエモート）が多かった場面を見つけ、そこから再生できるようにする。競合（ClipIt のキーワードの推移、VOD Highlight Analyzer・VODPeek のエモートの絞り込み）を参考にした。見た目は [分析画面](../screens/analysis.md)（案 A）と既存のルール（[配色 3](../design/colors.md#3-グラフの系列色)・基本 4）の組み合わせで、新しい種類の画面ではない。

## 使う人と最初の画面

[分析画面](../screens/analysis.md) の表のとおり（変わらない）。言葉の入力欄はグラフの枠の中、グラフの下に置く。375px の最初の画面の見え方（グラフの上の部分まで）は変えない。

## 受け入れ条件

### 数え方（`src/lib/term.ts` の1か所）
- 言葉は前後の空白を除き、NFKC で正規化して小文字にしたものを、同じく正規化・小文字にしたコメントに含むかで判定する。1つのコメントに何回あっても1件。
  - 「LOL」と「lol」、「ｗｗｗ」と「www」、「ＫＵＳＡ」と「kusa」は同じ。
  - スタンプは本文にある名前（YouTube は `:name:`、Twitch は絵文字の名前そのまま）を含むかで数える。`:` をつけても、つけなくても入力できる。
- 空（空白だけを含む）・101 文字以上の言葉は受け付けない。
- DB 側は `lower(normalize(body, NFKC))` と `strpos` で、JS と同じ規則にする。見本（`tests/fixtures/term-samples.ts`）で JS と Postgres の判定が同じになることをテストする。

### API
- `GET /api/jobs/:id/buckets?term=言葉` は、その言葉を含むコメントだけを30秒ごとに数える。区間は絞り込まない集計と同じ（0件の区間も含む）。動画開始前のコメントは除く。
- `term` は1回だけ。2回以上・空・101 文字以上は 400。`q`・`xq`・`user`・`xuser`・`laugh` と同時には使えない（`term` があるときそれらは無視せず 400）。
- DB の表は変えない（その場で数える）。分析が完了していないときは 409。

### 画面
- グラフの枠の、グラフの下に「言葉・スタンプを重ねる」入力欄と「追加」ボタンを置く。最大 2 つまで。追加した言葉は札（チップ）で並べ、×（44px）で外せる。2 つあるときは入力欄を使えなくし「2つまで」と補足を出す。
- 同じ言葉（正規化後）の追加・空・長すぎ・3つ目はお知らせでなく入力欄の下の補足文で断る（既存の絞り込み欄と同じ）。
- 言葉ごとに、グラフの棒の上に折れ線を重ねる。1つ目は `--chart-2`、2つ目は `--chart-3`（配色 3）。札の左に同じ色の印（■）を付け、色だけで見分けない。
- 線の縦軸は右側に置き、言葉の最大値に合わせる（棒の軸とは別。右軸の見出しは「言葉（件）」）。左の軸は今までどおり。
- 「すべて｜笑い」の切り替えと同時に使える（棒は今までどおり切り替わり、線は言葉だけを数える）。絞り込み欄の絞り込みの影響は受けない。
- 見出しの下に、言葉ごとに「「言葉」N / 全 M 件」を出す。
- 棒の上にいる間・選んだ棒の説明に、言葉ごとの件数を足す（「0:12:30 から 笑い 3 件・「草」2 件」）。
- 線が描かれている所の棒を押すと、今までどおりその時刻から再生する（線は押せる対象にしない。操作は棒だけ）。
- 言葉の数を読み込めた時点で線を描く。読み込み中・失敗した言葉の線は描かない。失敗したときはお知らせ「「言葉」の数を読み込めませんでした。」（基本 8-1）。
- 言葉は札から外せば線も消える。拡大・選んだ棒は言葉を変えても保つ（グラフを作り直さない）。
- 言葉のコメントが0件のときは、線を引かずに札に「0 件」と出す。
- 375・1024・1440px で横スクロールが出ず、375px でも入力欄・追加ボタンが1行に入る。

## 範囲外

- 言葉ごとの棒グラフ（線だけ）。
- 正規表現・あいまい検索・言葉の保存（ログイン後の保存は #7 以降）。
- 3つ以上の言葉。
- 線を押して再生すること。
- 笑いの判定（#41）と言葉の仕組みの統合（笑いは判定の正規表現、言葉は部分一致で性質が違うため、API は `laugh` と `term` を分けたままにする）。

## 仮定

- 「#41 の仕組みを広げる形」は、同じ `/buckets` の API に `term` を足し、画面は同じグラフ部品に線を足す形にした。別の API・別のグラフ部品は作らない。
- 棒（コメント数）と言葉の数は桁が違うので、線は右の別軸にした。同じ軸だと線が底に張り付いて読めないため。
- 言葉は部分一致（「草」は「大草原」にも一致）。単語境界の判定は言語によって難しいため。
- 言葉は絞り込み欄のワードとは独立にした。重ねて見る道具と絞る道具は目的が違うため。
- スタンプの名前は、取得時にコメント本文へ入っているテキストで数える（YouTube は `:name:` の最初の呼び名、`chat-parse.ts`）。画像そのものは数えない。
- 保存はしない（画面を開き直すと消える）。ログイン後の保存は #7 以降。
- DB の変更なし。リスクは medium のまま。
