# #25 分析画面の補助（平均コメント数・再生位置・±N秒の移動）

## 目的

アーカイブを見返す人が、配信全体のコメントの多さの目安（30秒あたりの平均）と今の再生位置を一目で確かめ、「‹ N 秒 ›」で再生位置を前後に動かして、気になった場面の少し前後を見直せるようにする。旧版（CommentStats・PlaybackTime・SeekControl）の移植。見た目は [分析画面](../screens/analysis.md)（案 A）の部品の組み合わせで、新しい種類の画面ではない。

## 使う人と最初の画面

[分析画面](../screens/analysis.md) の表のとおり（変わらない）。3つはグラフの枠の下に置く「再生の補助」の行にまとめ、375px の最初の画面（グラフの上の部分まで）の見え方は変えない。

## 受け入れ条件

### 平均コメント数
- 分析が完了しているとき、「コメント 累計 N 件」と「30秒あたり 平均 X 件」を表示する。累計は既存の `totalComments`。
- 平均 = 累計 ÷ 30秒区間の数（グラフの全区間。0件の区間も含む）。小数第1位まで表示（`12.3`）。
- コメントが0件（区間が0）のとき、平均は `0`（NaN・Infinity を出さない）。
- 絞り込み中でも、この表示は配信全体の値のまま変えない。
- 計算は `src/lib/` の関数に切り出し、テストする（0件・1区間・割り切れない場合の丸め）。

### 再生位置の表示
- 今の再生位置を `h:mm:ss`（既存の `formatTime`）で表示する。約1秒ごとに更新する。
- プレイヤーが準備前・読み込み失敗のとき、または分析が未完了のときは `0:00:00`。
- YouTube・Twitch どちらのプレイヤーでも同じ動き（共通の `PlayerHandle.getTime`）。
- 更新のたびに読み上げられないよう `aria-live` にはせず、ラベル「再生位置」を付ける。

### ±N 秒の移動
- 「‹ N 秒 ›」を表示する。N は数字の入力欄で変えられ、初期値は 10。
- 「›」で今の再生位置の N 秒後へ、「‹」で N 秒前へ動かし、再生する（既存の `seek`。グラフ・チャットの時刻と同じ動き）。
- 移動先は 0 秒未満にならない（0 に丸める）。動画の長さを超える移動はプレイヤーに任せる。
- N は 1〜3600 の整数。空・0・負・小数・範囲外のときは、ボタンを押しても動かさず、入力欄に補足の文字（「1〜3600 の整数で入力してください」）を出す。
- 入力欄の途中の編集（いったん空にして打ち直す）を妨げない。
- ボタン・入力欄とも高さ 44px 以上、押せる幅 44px 以上。キーボードで操作でき、ボタンにはラベル（「N 秒前へ」「N 秒先へ」）を付ける。
- 分析が完了していない（プレイヤーがない）ときは、ボタンを押せない状態にする。
- 移動先の計算と入力の検証は `src/lib/` の関数に切り出し、テストする。

### 確かめ方
- 平均の計算・移動先の計算・入力検証はユニットテスト。
- 画面は実際に動かして 375・1024・1440px で、横スクロールが出ず、押す場所が 44px 以上であることを確かめる。YouTube・Twitch の実機再生は、取得できる環境でのみ確かめ、できなければ PR に書く。

## 範囲外

- 動画の長さの取得・長さを超える移動の制限。
- 絞り込み条件に応じた平均の表示。
- N の保存（再読み込みで初期値 10 に戻る）。
- 再生位置の 1 秒未満の更新。

## 仮定

- 旧版の「平均」の定義は、累計 ÷ 区間の数と仮定した（Issue の「30秒あたりの平均コメント数」から）。区間の数は最後のコメントの区間までなので、動画末尾の無言の部分は含まない。
- 置き場所は、グラフの枠の下の1行（PC は左の広い列、スマホは縦積みでグラフの下）。
- 区間の数は、既存のグラフ用データ（`/api/jobs/:id/buckets`）の長さから得る（API・DB の変更なし）。
- 再生位置の更新は、既存のグラフの縦線と同じ約1秒ごとの取得を使う。
