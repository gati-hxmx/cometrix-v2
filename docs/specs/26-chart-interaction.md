# #26 グラフの細かい操作感（拡大・横移動・目盛り・ホバー表示・再生位置）

## 目的

長い配信のアーカイブを見返す人が、グラフの一部を拡大して区間を絞り、目盛りと表示で時刻と件数を読み取り、その時刻から再生できるようにする。旧版（Chart.js＋zoom）の操作を移植し、v2 のスマホ操作（なぞって選ぶ・‹ ›。#4）と両立させる。見た目は [分析画面](../screens/analysis.md)（案 A）に従い、新しい種類の画面ではない。

## 使う人と最初の画面

[分析画面](../screens/analysis.md) の表のとおり（変わらない）。拡大の初期状態は「全体」で、最初の画面の見え方は変えない。1440px でグラフが最初の画面に入らない件（#20）は、PC の配置（動画の高さの上限）を見直して、グラフの上端が見えるようにする。

## 受け入れ条件

### 拡大・縮小（横方向）
- 表示範囲は元の30秒区間（まとめる前）の番号 `[start, end)` で持つ。初期は全体。範囲内の区間を、これまでと同じ規則（最大120本）でまとめて棒にする。拡大すると棒が細かく分かれ、最小は30秒1本ずつ。
- PC：グラフ上で Ctrl＋ホイール（`ctrlKey` 付きの wheel。トラックパッドのピンチも同じ）で、ポインタの下の時刻を動かさずに拡大・縮小する。Ctrl なしのホイールは通常のページスクロール。
- スマホ：グラフ上で2本指のピンチで、2本指の中心の下の時刻を動かさずに拡大・縮小する。
- 下限：表示範囲は最小 `MIN_RANGE`（10区間＝5分）より狭くならない（全体が10区間未満なら全体）。上限は全体で、全体で縮小しても変化しない。
- 範囲が区間数を超えない・負にならない・順序が逆転しない（境界値のテストあり）。

### 拡大中の横移動
- PC：拡大中、グラフ上のマウスのドラッグで横に動かす。動かした距離は、そのとき表示している時間に比例する。範囲の端で止まる。ドラッグ後に棒を選んだことにしない（ドラッグ終了の click は無視）。
- スマホ：拡大中は2本指のドラッグで動かす（ピンチと同時でもよい）。1本指のなぞりは今までどおり「棒を選ぶ」で、動かさない。縦のページスクロール（1本指の縦）も妨げない。
- 全体表示のとき、ドラッグは何も起こさない（マウスのクリックは今までどおり選択）。
- 拡大中に、‹ › やキーボードで選択が範囲の外へ出るときは、選択した棒が見えるよう範囲を自動で動かす。

### 目盛り
- 横軸に時刻（`h:mm:ss`）を、最大10本程度に間引いて出す。間隔は 30秒・1分・2分・5分・10分・15分・30分・1時間・2時間 … のうち、本数が10以下になる最小のもの。目盛りは間隔の倍数の時刻に置く。拡大・移動に追従して変わる。
- 縦軸にコメント数の目盛り（0 と、きりのいい数 3〜5本）を出す。最大値はいまの表示範囲の最大の棒に合わせる（拡大するとスケールが変わる）。
- 目盛りの文字は `--muted`、グリッド線は `--line`。375px で重ならず、横スクロールが出ない。

### ホバー・選択の表示
- 棒にマウスを乗せると、その棒が濃くなり、棒の近くに「時刻・件数」のふきだしが出る。ふきだしは画面の端ではみ出さない。今までの上の1行表示は残す（スマホのなぞり表示と読み上げ用）。
- 押した棒は選択中として、配色ルールの強調色（旧版の赤にあたる）で塗り、別の棒を押すまで残す。色だけに頼らず、今までの outline も残す。
- いちばん多い棒の `--accent` は変えない。ピークと選択が同じ棒のときは、選択の見た目を優先する。

### 足す操作
- 拡大中だけ、「全体に戻す」ボタン（高さ44px以上）を出す。押すと表示範囲が全体に戻る。全体表示のときは出さない。
- いま再生している位置を、グラフに縦線で示す。プレイヤーの時刻（約1秒ごとに取得）に追従する。表示範囲の外のとき、プレイヤーが準備前・失敗のときは出さない。線は幅2px で、操作（押す・なぞる）を邪魔しない。
- グラフにフォーカスがあるとき ← → で前後の棒へ選択を動かして再生する（‹ › と同じ動き）。Home／End は最初／最後の棒。`+`／`-` で拡大・縮小（キーボードだけでも拡大できる）。
- 棒の選択（押す・Enter／Space・なぞって離す）は、拡大中でも、押した棒の開始時刻から再生する。

### 既存の動き（壊さない）
- スマホで1本指でなぞると指の下の棒を示し、離した所から再生する。‹ › は今までどおり。
- 絞り込み（#5）でデータが差し替わっても、拡大範囲は保つ（区間数が変わったときは範囲を収まるよう直す）。コメントが0件のときの文言は今までどおり。
- 別のジョブに移ったときは、拡大は全体に戻る。

### 画面の配置・確認
- 375px・1024px・1440px で崩れず、横スクロールが出ない。操作できる範囲は 44px 以上。
- 長い配信（例：6時間＝720区間）で、一部を拡大して区間を選び、その時刻から再生できる（PC・スマホとも）。

### テスト
- 拡大範囲の計算（ホイール・ピンチ・横移動・下限・上限・端の丸め）は純粋な関数にして単体テストを書く。目盛りの間隔・縦軸の目盛りの選び方も同様。

## 範囲外

- 縦方向の拡大、グラフの画像保存。
- 区間の長さ（30秒）の変更、データ取得 API の変更。
- #25（平均コメント数・±N秒の移動）、#28（ダークモード）、#6（Twitch）。
- DB スキーマの変更（しない）。

## 仮定

1. グラフは自作のまま足す。新しい依存は入れない（リスク基準 8 を避ける）。
2. 旧版の `minRange` の値は不明なため、5分（10区間）を仮の下限にする。
3. 旧版の「赤」の選択色は、配色ルールの強調色に置き換える（Issue の指定どおり）。
4. 再生位置は、プレイヤーの `getCurrentTime()` を約1秒ごとに読んで取る（IFrame API にイベントがないため）。
5. 拡大中の棒は範囲内の区間を最大120本にまとめる（拡大するほど細かくなり、最小は1区間1本）。
6. 色は `docs/design/colors.md` の既存の色で作る。足りない場合だけ、PR に提案を書く（基本ルールは変えない）。
7. #6（PR #22）と並行のため、触るのは `BucketChart.tsx`・`chart.ts`・`AnalysisView.tsx`・`YoutubePlayer.tsx` の最小限にとどめる。
