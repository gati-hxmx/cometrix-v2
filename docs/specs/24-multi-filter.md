# #24 絞り込みを旧版と同じにする（複数ワード・除外ワード・除外ユーザー）

## 目的

#5 の絞り込み（キーワード1つ・ユーザー名1つ）を、旧版 ChatFilter と同じ4種類（含めるワード・除外ワード・含めるユーザー・除外ユーザー、それぞれ複数）に広げる。一覧とグラフの両方に反映する。

## 使う人と最初の画面

[分析画面](../screens/analysis.md) のチャット一覧の上の絞り込み欄だけを変える。375px の最初の画面（ヘッダー・タイトル・動画・グラフ）は変えない。

## 入力の形（既存の部品の組み合わせ）

- 4つの欄（含めるワード／除外ワード／含めるユーザー／除外ユーザー）を、それぞれ「ラベル・文字入力・［追加］ボタン」の1組にする。
- 追加した語は、入力欄の下にチップ（語＋×ボタン）で並べる。×で1つ消せる。Enter でも追加できる。
- 除外の欄は、チップに `--danger` 系の色と「除外」の文言でも区別する（色だけに頼らない）。
- 追加・削除したら、すぐ（待ち時間なしで）一覧とグラフに反映する。入力途中の文字は反映しない（追加するまで絞り込みに入らない）。
- 「クリア」は4種類すべてのチップを消す。

## 受け入れ条件

### ロジック
- 含めるワードを複数入れたとき、本文にどれか1つでも含まれるコメントだけが残る（OR）。
- 除外ワードを複数入れたとき、本文にどれか1つでも含まれるコメントは残らない。含めるワードと重なっても除外が優先する。
- 含めるユーザーを複数入れたとき、名前にどれか1つでも含まれるコメントだけが残る（OR）。除外ユーザーに当たる名前は、含めるユーザーに当たっても残らない。
- 含めるワードと含めるユーザーの両方があるときは、両方を満たすもの（AND）。
- すべて空のときは絞り込まない。
- 部分一致で大文字小文字を区別しない。語の前後の空白は除く。空の語は追加できない。同じ語（正規化後）は重複して入れない。
- `%`・`_`・`\` は文字として扱う。

### 上限（異常系・境界）
- 1語は 100 文字まで。1種類あたり 10 語まで。上限に達したら追加ボタンを無効にし、理由を欄の下に出す。
- API は上限超過・不正で 400。

### API（読み取り専用・スキーマ変更なし）
- 繰り返しのクエリで指定する：`q=a&q=b`（含めるワード）、`xq=…`（除外ワード）、`user=…`（含めるユーザー）、`xuser=…`（除外ユーザー）。`/messages` と `/buckets` の両方。
- 旧来の `q=`・`user=` 1つだけの呼び出しは、これまでと同じ結果になる（互換）。
- 空文字の値は無視する。応答の形は変えない。
- 判定・正規化・クエリの読み取り・SQL 条件の組み立ては `src/lib/chat-filter.ts` の純粋関数にしてテストする。

### 画面
- 絞り込み中、グラフは一致数で描き直され、「絞り込み中：一致 N / 全 M 件」を出す（#5 と同じ）。一覧は再生位置に近い一致コメントから出る。
- 一致0件は「一致するコメントがありません」（一覧・グラフ）。
- 絞り込みは URL に残さない。

### アクセシビリティ
- 各入力にラベルを付ける。チップの×は「〇〇を削除」と読めるラベルと 44px 以上の押せる範囲を持つ。追加・削除の結果は件数の `aria-live="polite"` で知らせる。

## 範囲外
- 正規表現・完全一致の切り替え、URL への保存、旧版のその他の機能（CommentStats など）。
- DB スキーマ・索引の変更。

## 仮定
1. 「どれかを含む」は部分一致。除外は含める条件より優先（Issue の完了条件どおり）。
2. 入力は「追加するまで反映しない」にする。複数語の入力では、打ちかけの文字で絞り込みが揺れないため。#5 の 300ms 待ちの即時反映は廃止する。
3. 上限 10 語は URL 長と SQL の重さを抑えるための仮の値。
4. 新しい見た目の方向性は不要：既存の「チップ」「ボタン」の組み合わせで作る（design スキルは使わない）。
5. リスクは `risk:medium`（スキーマ変更・認証・課金に触れない）。
