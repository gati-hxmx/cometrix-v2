# #2 最初の見た目を決める（トップと分析画面）

## 目的

配信者や切り抜き作成者（仮定）が、アーカイブのチャットのコメント数から盛り上がった場面を探せるように、トップと分析画面の最初の見た目（配色と画面の形）をオーナーに選んでもらい、ルールにする。

## 受け入れ条件

1. design スキルの見本として、トップと分析画面を、スマホ（375px）と PC（1440px）それぞれ4案ずつ用意し、スクリーンショットを Issue に載せている。
2. 見本は `src/app/globals.css` と同じ CSS 変数を使い、架空のデータで、空のとき・コメントが多いときの見え方を1枚ずつ含む。絵文字・強い色の面は使わない。
3. オーナーが案を選んだとき（「A と C を混ぜて」も可）、選ばれた形が `docs/design/` の該当章に書かれ、返事の言葉が `docs/design/history.md` に1行足されている。返事が「混ぜて」「直して」の場合は、次の2〜4案を出して再度選んでもらう。
4. 配色が変わる場合は、`src/app/globals.css` の変数の値と `docs/design/colors.md` が一致している。
5. `docs/design/README.md` の「使う人」の表から「仮定のため…確かめる」の注記が外れ、オーナーの確認結果に更新されている。
6. `docs/screens/top.md` と `docs/screens/analysis.md` があり、それぞれ冒頭に「使う人と最初の画面」の表（だれが・どこで・何をしに開くか、375px でスクロールせずに見えるもの）、配置、状態（空・読み込み中・エラー・コメントが多い）を書いている。
7. 分析画面の仕様に、グラフ・動画の再生・チャット一覧が1つの画面で行き来できること、グラフの時刻クリックで動画がその時刻から再生されること（実装は #4・#5）を、画面の形として書いている。
8. `scripts/check` が通る。

## 範囲外

- 取得・集計（#3）、分析画面の実装（#4）、チャット一覧と絞り込み（#5）、Twitch（#6）、ログイン（#7）、マイページ（#8）
- 実際に動く画面の実装。この Issue は「見た目の決定とルール化」までで、実画面は #4 以降で作る。トップのみ、選ばれた配色と形を反映した最小の画面（URL 入力欄と見出し）を置いてよい。

## 仮定

1. 使う人は Issue の仮定どおり（PC が中心、ときどきスマホ）。オーナーが案を選ぶときに併せて確かめる。
2. 旧版（Cometrix の `frontend/src/views`）は参考にとどめ、配色・部品は `docs/design/` に合わせて作り直す。
3. トップは「URL 入力欄 + 使い方の一言 + 最近の分析」の簡素な形、分析画面は「動画・コメント数グラフ・チャット一覧」を中心とした形を出発点に案を作る。理由：#4・#5 の完了条件に合わせるため。
4. コードの変更は見本と最小の画面のみ（DB・認証・課金なし）のため `risk:medium`。見た目の方向性はオーナーが選ぶので、案を出したら `needs-human` を付けて待つ。
5. Tailwind・Lucide の導入は、形が決まってから #4 以降で行う（依存追加として別途リスク判定する）。
