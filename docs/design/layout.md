# 画面づくりの基本ルール

どの画面にも共通する配置と動きの決まりです。使う人と考え方は [デザインの入口](README.md)、部品は [部品づくり](components.md)、色は [配色](colors.md)、絵は [アイコン](icons.md) にあります。画面ごとの決まりは `docs/screens/<画面>.md` に書きます。

この文書の中の「（例）」は Hana での使い方です。アプリに合わせて置きかえ、決まりそのものは変えません。

## 1. PC とスマホは別々に最適化する

- 同じ画面を縮めるのではなく、PC とスマホでそれぞれ使いやすい配置にします。
  - PC：横に並べて広く使います（2列のフォーム、左右2列の詳細、カードを横に複数）。
  - スマホ：1列で上から順に並べ、ボタンは大きく、横幅いっぱいにします。
- 画面幅の区切り：

  | 幅 | 配置 |
  | --- | --- |
  | 899px 以下 | スマホの配置（下にメニュー） |
  | 900px 以上 | PC の配置（左にメニュー） |
  | 1100px 以上 | 詳細画面や設定の枠を左右2列に |
  | 1400px 以上 | 本文を最大 1560px まで広げ、右側が空きすぎないようにする |

- どの画面も、幅 375px で横にはみ出さないこと。入りきらないときは、文字を小さくせずに折り返します。
- **スマホの最初の画面**：どの画面も、仕様の最初の表に「375px で開いて、スクロールせずに見えるもの」を1行で決めます。そこには、その画面を開いた目的の答え（いちばん大事な数・次の予定・次にすること）を入れます。説明・設定・畳んだ一覧で最初の画面を埋めません。
- スマホで選択肢が多いとき（5つ以上）は、2列に並べて縦の長さを抑えます。
- **スマホは指で押しやすく、PC は一度にたくさん見せます**。スマホは大きな数字と、アイコンを上・名前を下にした大きな四角の札（44px 以上、8）で、押すと詳しく出します。PC は同じ四角の中に中身の札を並べ、押さなくても見えるようにします。
- PC では、1問ずつ進む入力も、全部の質問を1ページに出します。スマホは1問ずつのままです。

経緯：2026-11-01（[経緯](history.md#基本-1-スマホの最初の画面)）。

## 2. ヘッダー（画面の一番上）

- 左にロゴ。右は左から順に **言語 → 通知 → ユーザーアイコン** を並べます。言語が1つなら言語は置きません。
- **言語の切り替え**は、1回の押しまちがいでアプリ全体の言語が変わらないようにします。ふだん使う画面では**いまの言語の印 ▾** を1つだけ置き、押すと [小さなメニュー](components.md#5-9-小さなメニュー) で言語の行（言語の名前はその言語のまま）を選びます。いまの言語の行は色と ✓。ログイン前など一度しか選ばない所は、印のボタンを並べてすぐ切り替えてもかまいません。
- 通知のボタンはアイコンにし、件数はボタンの上の**灰色の丸**で出します（赤は今日やらないと困るものだけ、[配色 2-1](colors.md#2-1-赤と--は今日やらないと困るものだけ)）。アイコンに添える言葉は [部品 3-1](components.md#3-文字の表示はアイコン中心にして場所を取らない) のとおりです。
- ログアウト・文字の大きさ・使い方は、ユーザーアイコンを押したメニューにまとめます。
- やることのボタンはヘッダーに置きません。やることはホームに並べ、その数はメニューの「ホーム」の灰色の丸で出します（8-2）。
- スマホでも、ヘッダーは1行に収めます。

### 2-1 上のメニューと本体のあいだには何も置かない

- **ヘッダー・ページの上の枠（対象の切り替え・‹ 期間 ›・表示の切り替えなど）と、そのページの本体（カレンダー・表・一覧）とのあいだに、注意書き・お知らせ・バナー・説明の1行を出しません**。新しい画面でも作りません。
- 伝える必要があるものは、**関係する要素の中か近く**に置きます。

  | 伝えたいこと | 置く場所 | 例 |
  | --- | --- | --- |
  | 対応が要ること | 関係するマス・行・札・ボタンの印（⚠・＋・点線） | 入力もれの日のマスに点線と ⚠ |
  | できない理由 | そのボタンの場所 | 「⚠ 確定できない n ▾」 |
  | 表・カレンダーの見方や数え方 | 本体のすぐ下の小さい字か、見出しの横の ⓘ。ただし印は単位や短い言葉で読めるようにし、説明の行はできるだけ置かない（[考え方 3](README.md#見た目を選ぶときの考え方)） | 表の下の注 |
  | 操作の結果 | お知らせ（8-1） | 一部できなかったときも「できませんでした」 |
  | 状態（確定済み・オン/オフ） | その箱の中 | 設定の行の値 |
  | 取り返しのつかない操作の確認 | その操作の箱・行の中（[部品 4-2](components.md#4-操作のしかた)） | データのリセット |

- 上の枠の中に小さく書くこと、本体の下・パネルの中・ⓘ の中に書くことはかまいません。
- 絞り込みの状態と ✕ は、上の枠の続きとしてその1行だけ置けます。

経緯：2026-11-04（[経緯](history.md#基本-8-押しやすさお知らせやること)）。

## 3. ページの見出し

- メインメニューから開く画面では、一番上の大きな見出しを出しません。どの画面かは、メニューの選択中の表示でわかるためです。
  - 読み上げ用の見出しは、見えない形で残します。
  - 下のメニューから開く画面には「‹ 戻る」も出しません。
- 詳細画面や入力画面では、名前やタイトルを見出しに出します。

## 4. 切り替えボタンの位置

- 店・チーム・プロジェクトなど「対象」は増えていく前提で、いくつになっても上の枠の高さが変わらないようにします。対象のタブは並べません。見た目は [部品 5-4](components.md#5-4-対象の札と名前-) です。
  - **全部まとめて見る画面**：一覧のすぐ上の**対象の札**で絞るだけです。合計の数字はいつも全部のままです。
  - **対象ごとに作業する画面**：上の枠の**左端**に**「名前 ▾」の札1つ**。
- 表示の切り替え（期間・並べ方・タブなど）は**右端**に置きます。
- 表示の切り替えは、「名前 ▾」や対象の札（離れた丸い札）と見分けられるよう、つながった札（「人別｜時間別」の形）にします。上の枠は白い枠の中に入れます。
- PC の表示の切り替えは、つながった札にアイコンを並べ、**選んでいるものだけ名前を出します**。ほかはマウスを乗せたときと読み上げで名前を出します。スマホは [部品 3-1](components.md#3-文字の表示はアイコン中心にして場所を取らない) のとおりです。
- スマホで1行に入らないときは、表示の切り替えを次の行の右端に回します。

経緯：2026-10-29、2026-11-06（[経緯](history.md#基本-4-切り替えボタンの位置)）。

## 5. 同じ情報は1か所にまとめる

- 同じ情報を画面の2か所に出しません（例：上部の「今の時給」と下の「時給の履歴」）。
- 詳細画面や設定のページは「**今の値を見て、押して変える**」一覧にし、[設定の一覧](components.md#5-1-設定の一覧アイコン名前右に今の値) の形で並べます。履歴や入力欄は、押したときだけ出します。
- 似た一覧は1つにまとめて切り替えます（例：「これから」と「これまで」）。
- 操作ボタンは、よく使うものだけを出します（PC は2つまで、スマホは1つ）。あまり使わない操作は「その他 ▾」にまとめます（スマホは下からせり上がる一覧）。
- 同じ作業の流れに属する画面は分けずにまとめます。
- 設定は「設定」ページに集めます。作業の画面の中で見ながら決めるものだけはその画面に残し、その行は設定ページの同じ項目のパネルを開きます。同じものを決める場所を2つ作りません。
- 設定ページは**全体で共通のものと対象ごとのもの**で分けます。対象ごとに決めるものは、対象の行から開く1つのパネルにまとめます。
- 「決まり」と「その回だけの変更」があるものは、決まりのパネルの下に作ってある回を並べ、［変更］でその回だけ直します。
- 状態の印は、例外だけに付けます（例：「下書き」に印、ふつうの「公開済み」は印なし）。

経緯：2026-10-27（[経緯](history.md#基本-5-同じ情報は1か所にまとめる)）。

## 6. 変更はページを移らずにパネルで

### 6-1 パネルにするかの判断

パネルは「その場で済まないとき」の手段です。上から順に当てはめて、最初に当てはまった形を使います。

1. **その場で直せる** → パネルにしません。ドラッグ、− / ＋、自動保存のメモ、押すとすぐ保存する選択ボタンなど、1回の操作で終わるもの（[部品 2](components.md#2-文字を打たせない)）。
2. **1つ選ぶだけ（やること・対象・表示・値）** → 押した場所のすぐ下に出る [小さなメニュー（▾）](components.md#5-9-小さなメニュー)。右クリック・長押し・「その他 ▾」・見出しの ▾ も同じです。選ぶとすぐ切り替わって閉じ、画面を暗くしません。選ぶものが12個を超える、または1つずつに印や説明が2行以上あるときだけ 4 のパネルにします。
3. **見るだけの補足**（内訳・説明・計算式） → その場で畳んで開きます。数行なら、ⓘ を押すとすぐ下に出る小さな枠でもかまいません。
4. **2つ以上の入力や確認がある、または一覧の行の詳細を見る** → 次の2つに分けます。
   - **新しいものを1つ登録する** → **画面の中央に出る白い枠**。「＋ 〇〇を追加」から開き、1つ作って終わる入力です。
   - **あるものを見る・直す** → **サイドパネル**（PC は右、スマホは下）。
   - **例外：カレンダーや表のマスから入れるものは、追加でもサイドパネル**。押したマスで「だれ・いつ」が決まり（6-2）、元の表を見ながら何件も続けて入れるためです（白い枠だと表の真ん中が隠れます）。
   - 幅：入力欄が1列なら 520px（白い枠は 560px）、写真・2列・表が要るなら 760px。
5. **何件も続けて入力し、元の画面を見ながら進める** → PC の広い画面では横に常に出します（パネルではなく画面の一部）。スマホはパネル。
6. **それ自体が1つの作業になる**（印刷、CSV、詳しい明細、操作履歴、長い表） → 別のページ。

あわせて守ること：

- 確認やエラーはパネルにしません。確認はその場（パネルの中か、その行・箱の中）で聞くか「元に戻す」にし（どちらにするかは [部品 4-2](components.md#4-操作のしかた) の表）、エラーはお知らせにします（8-1）。ブラウザの確認ダイアログは使いません。
- スマホではパネルが画面の9割を隠します。元の表を見ながら入力する必要があるなら、4 ではなく 1 か 5 にします。
- 小さなメニューは、PC もスマホも押した場所のすぐ下に出します（スマホは横いっぱい）。高さは画面の6割までで、それ以上は中でスクロールします。
- パネルの上にパネルを重ねるのは2段までです。3段目が要るなら、そこは別ページにします。

### 6-2 パネルの決まり

- 詳細画面での変更は、ページを移らず**パネル**で開きます。
  - PC：画面の**右から**出るパネル（通常幅 520px、項目が多いときは 760px）
  - スマホ：画面の**下から**せり上がる画面
  - **新しく登録する白い枠**（6-1 の 4）は、PC でもスマホでも**画面の中央**に出します。画面の端から少し離し、角は丸くします。つまみと下に引いて閉じる操作はありません。それ以外の決まりはパネルと同じです。
- パネルは「閉じる」か、暗い部分を押すと閉じます。保存ボタンはパネルの下に固定します。
- 閉じるボタンは見出しの右に「✕ 閉じる」。初心者向けに「閉じる」の文字も残します。
- スマホでは上につまみを付け、下に引くと閉じます。スマホの「戻る」でもパネルだけ閉じ、ページは離れません。
- 入力の途中で閉じようとしたとき（✕・暗い部分・Esc・下に引く・戻る）は、パネルの中で「入力をやめて閉じますか」を1回だけ聞きます。何も入れていなければすぐ閉じます。
- 下に固定するボタンは、右に主なボタン1つ、その左に「キャンセル」。スマホは横いっぱいに並べます。主なボタンは「保存」ではなく「この時間で保存」のように、押すと何が起きるかを書きます。
- 閉じたら、開く前に押した行・マスに戻ります（画面の位置とキーボードの位置）。
- **スマホでカレンダーや表の項目を押したら、下から出るシートで済ませます**。シートの上の1行に「‹ 11/03(火) ›」のような前後へ移るボタンを置き、その項目の追加などのボタンもシートの中に置きます。別のページへ移らせません。
- **続けて入れるパネル**：下のボタンは2つまで（［下書き］［登録して次へ ›］のように、右が次へ進むボタン）。3つ目の操作は、パネルの上の1行の右に置きます。上の1行に「いま3件目」のように今どこかを出し、次の1件には前の1件の値を最初から入れておきます（[部品 2-2](components.md#2-文字を打たせない)）。
- 入力ミスがあったときは、パネルを開いたまま、入力した内容を残して戻します。保存できたら元の一覧（同じ条件）に戻ります。
- パネルの中の長い説明は畳みます。
- 押した場所で「だれ・いつ」が決まっているときは、パネルで選び直させません。1行で見せ、「変更」を押したときだけ選べるようにします。
- PC でマウスで直接直せる画面でも、指で使うときは同じことが押す → パネルでできるようにします（[部品 4-1](components.md#4-操作のしかた)）。
- 中央に出す白い枠は、新しく登録するときだけにします。見る・直す・履歴・はじめての案内は、右（スマホは下）のパネルで出します。
- ヘッダーの小さな一覧（通知）は、PC はボタンの下に、スマホは下からせり上がる形で開きます。

経緯：2026-10-10〜11-05（[経緯](history.md#基本-6-パネル)）。

## 7. 詳細画面の配置

- **一番上の1行**：名前と、よく使う操作のボタン（2つまで、5）。状態の印は例外だけ（5）。
- **PC もスマホも1列**：[設定の一覧](components.md#5-1-設定の一覧アイコン名前右に今の値) の行を見出しごとの枠に並べます（PC は幅 900px まで）。日付が主役の情報は、別の画面へのリンクの行にします。
- **選ぶもの**は行の中に選ぶ四角をいつも出し、押すとすぐ保存。**そのほか**は値のボタンで、✎ はその場で入力、› は行の下（スマホは画面いっぱい、上に「‹ 名前」）に中身を開きます。
- 保存したら、その行のすぐ下に「✓ 保存しました · 元に戻す」を出します（お知らせには出しません）。
- 対応が要る行は値を「⚠」にし、ホームのやることに出します（8-2）。

経緯：2026-10-29〜11-07（[経緯](history.md#基本-7-詳細画面の配置)）。

## 8. 押しやすさ・読みやすさ・お知らせ

- ボタンや押せる場所の高さは **44px 以上**にします。小さいボタン（‹ ›・変更・開く）も同じです。「?」「ⓘ」の丸は見た目は小さいまま、押せる範囲を 44px にします。
  - スマホ（900px 未満）は**幅も 44px 以上**にします。カレンダーや表のマスも同じです。並べると入りきらないときは、すき間を詰め、枠とすき間の半分まで押せる範囲を広げます。それでも入らない表は、表の中で横に送ります（右の端に影）。
  - PC の表の中の小さな札は、たくさん見せるために小さいままでかまいません。
- 文字は小さくしすぎません。入りきらないときは、文字を縮めずに折り返すか、並べ方を変えます。
- 「文字を大きく」を選んだときも崩れないこと（数字の並びは2列に減らすなど）。
- 色だけで意味を伝えず、文字や記号も添えます。
- 動き（パネルが出るときなど）は短くし、「動きを減らす」設定のときは止めます。
- **直してほしいこと（やること）は、ホームのやることにまとめます**（8-2）。画面の上に黄色い枠の注意は出しません（2-1）。画面の中では、関係する場所に印だけを付けます（点線と ⚠、行の「n件 未入力」の札、設定の行の値「⚠」など）。印1つで足りないところは [1行の印](components.md#5-6-1行の印と-) にします。
- **状態**（確定済み・締切済みで変えられない）は、やることではないので、その場に灰色の 🔒 と1文で出します。黄色にしません。
- **確認**（公開前のチェック、取り返しにくい操作の前に確かめること）は、その場（パネルの中か、その行・箱の中）に出したままにします。
- 入力欄のまちがいは消さずに、パネルの中に出したままにします。空のままでは保存できない入力欄は、見出しの右に赤い小さな「必須」の札を付けます。空でよい欄には何も付けません。

### 8-1 お知らせ（画面の下）

- **使うのは「自分がいま行った操作の結果」だけ**です：保存した・削除した・送った・コピーした・できなかった。ほかのものは次の場所に出します。
  - 対応が要ること → 関係する場所の印やパネルの中に残す注意（2-1）
  - ほかの人の動き → ヘッダーの通知（記録として残る、2）
  - 使い方の説明 → 使い方のパネル
  - 自動保存 → その場の小さな「保存しました」
- 操作の一部ができなかったときも「できませんでした」で出します。ページの上に黄色い箱は出しません。
- **種類は3つだけ**です。

  | 種類 | 見た目 | 出ている時間 |
  | --- | --- | --- |
  | できました | 緑の ✓ | 4秒 |
  | できました＋［元に戻す］ | 緑の ✓ とボタン | ✕ を押すまで |
  | できませんでした | 赤の ! | ✕ を押すまで |

- ［元に戻す］つきとできませんでしたは、**自分で ✕ を押すまで消えません**。読むのがゆっくりな人も、［元に戻す］や理由を見逃さないためです。別のページへ移ると消えます（移った先で操作の結果があれば、それが出ます）。
  - 戻せる時間に限りがあるときは（例：10分）、過ぎたら文は残して［元に戻す］のボタンだけ外します。
- できましたの4秒も、マウスを乗せている間・指で触れている間は消えません。✕ でいつでも閉じられます（押せる範囲 44px）。
- **文は1行で「何を・どうした」**：「〇〇 · 10/20 の予定を保存しました」。説明は書きません。できなかったときは「理由」と「どうすればよいか」を1文ずつ書きます。どの言語でも1〜2行に収めます。
- **「元に戻す」はお知らせの中に**置きます。押したら「元に戻しました」に変わります（[部品 4-2](components.md#4-操作のしかた)）。
- **位置と数**：**画面の下**に出します。PC は右下（幅 380px）、スマホは下のメニューのすぐ上に横いっぱい（下からせり上がる箱が開いていれば、その上）。閉じるまで残るので、上のメニューを隠さないためです。右下の＋はお知らせの上へよけます。ヘッダー・下のメニュー・右下の＋を隠しません。同時に出すのは3件までで、新しいものを上に。同じ文が続いたら1件にまとめます。
- **じゃましない**：お知らせに入力の場所（フォーカス）を移しません。パネルを開いたままでもパネルの上に出します。読み上げは、できなかったときだけすぐ読み、ほかはあとで読みます。

経緯：2026-10-11〜10-25、2026-11-13（[経緯](history.md#基本-8-押しやすさお知らせやること)）。

### 8-2 やること（ホーム）

- **やることはホームにだけ並べます**。ホームのいちばん上が**「今日やること」**で、いちばん急ぐものを**3つまで**、大きなボタン付きで並べます。残りは**「ほかにも n つ」**（PC は右の箱、スマホは押すと下から出るパネル）にまとめます。何もないときは「✓ 今やることはありません」。
- **急ぐ順はアプリで1か所に決めます**（関数1つ。プッシュ・メールなど外への通知と毎朝のまとめも同じ順と同じ文）。[配色 2-1](colors.md#2-1-赤と--は今日やらないと困るものだけ) の「今日」の段に入るものが先です。その行のアイコンは `--danger`（地は `--danger-weak`）、ほかは `--accent` です。前の日の残りは日ごとに並べず、1行（「前の日の分を終える · n日分」）にまとめます。
- **1行＝「何を・どうする」の1文＋下に1行＋ボタン1つ**（「きのう（11/12）の記録を入れる／A・B／［記録を入れる ›］」）。ボタンは、押すとその作業の場所かパネルが開くものか、元に戻せる操作だけにします。公開・確定のような取り返しにくい操作は、移った先の画面で言葉のボタン（[部品 3-3](components.md#3-文字の表示はアイコン中心にして場所を取らない)）で行います。
- **数は「つ」で数える1つだけ**：「今日やること 3つ」とメニューの「ホーム」の灰色の丸（PC は左のメニューの右端、スマホは下のメニューのアイコンの右上）は同じ数で、最大3です。行の中は「12人」「11日分」のようなふつうの言葉の単位にします。
- **ほかにも**の行は、アイコン・1文・下に1行・› の1行で、押すとその画面へ移ります。
- ヘッダーの通知は起きたことだけで、やること（しめきり前の未提出など）は出しません。画面の中は関係する場所の印と工程のボタンで知らせます。
- 数は数え方の表（12）のとおりにし、ちがう単位の数を足しません。設定で使わない仕事（15）と、その人の権限で見られない仕事は出しません。終わった仕事は自動で消えます。

経緯：2026-10-30、2026-11-04、2026-11-13（[経緯](history.md#基本-8-押しやすさお知らせやること)）。

## 9. 変えてはいけない決まり

アプリを始めるときに、オーナーの最初の指示からここに足します。次の3つはどのアプリでも守ります。

- 動かない機能を、動いているように見せるボタンやダミー表示で補いません。
- 試作品・デモのときは、その注意書きをすべての画面から見られるようにします（ヘッダーの札を押すと開く形。ヘッダーの下の帯にはしません、2-1）。
- お金・法律・個人に関わる数字や言葉は、実際とちがう意味に取れる書き方をしません（例：参考の集計額を「手取り額」と書かない）。

（アプリごとの決まり）

## 11. メニューと一覧

- メニュー：PC の左とスマホの下は、同じ項目を同じ順に置きます（5〜6個まで。「その他」は置きません）。使い方・サイトの地図・ログアウトは右上のユーザーメニューに置きます。
- 長い一覧は1件1行にして畳みます（「ほか n件」「それより前の〜（n件）」）。済んだものも畳みます。
- 一覧の行は、行全体を押せるようにします。同じ働きの「開く」ボタンを重ねて置きません。
- 画面の途中に、文字だけのリンク（「〇〇の一覧 ›」）を置きません。入口は行・札・パネルの中に置きます。
- 一覧の絞り込みは、選んだらそのまま表示します（「表示」「絞り込む」ボタンを置かない）。人などの一覧の表は、絞り込みと並び替えを見出しの行に置きます（[部品 5-8](components.md#5-8-一覧の表見出しの行で絞り込み並び替え)）。

経緯：2026-10-12・10-25（[経緯](history.md#基本-11-メニューと一覧)）。

## 12. 数え方（どの画面でも同じ数にする）

ホームのやること・工程バー・カレンダー・札などに出す数は、この表の決まりで数えます。画面の仕様にはこの表を指すだけにし、数え方を書き直しません。

| 数 | 数えるもの | 単位 |
| --- | --- | --- |
| （例）入力もれ | 始まった公開済みの予定で、記録がないもの。下書きとまだ始まっていない予定は数えない | 回 |
| （アプリごとに書く） | | |

- **数える範囲は画面ごと、数える条件は同じ**：範囲（その期間・今日までのすべてなど）だけが画面ごとに変わります。
- **1つの数は1つの関数で数えます**。どの画面も同じ関数を呼び、画面ごとに似た数え方を作りません。
- **単位を混ぜません**：「件・人・日」のちがう数や、ちがう期間の数を足して1つの数にしません。
- 新しい数を出すときは、まずこの表に1行足してから作ります。
- **同じ工程は、どこでも同じ名前・同じ順**にします。

## 13. 入口と行き先の約束

ホームのやることの行・工程バー・通知・⚠ の印は「入口」です。押した人は、そこで見た数の中身を見に来ています。行き先では次を守ります。

- **見に来たものが、375px の最初の画面に見える**こと。日を指して開いたら、その日を開き、スマホではそこまで動かします。行やパネルを指して開いたら、それを開いた状態にします。
- **全部の数から対象ごとの画面へ移るときは、⚠ のある対象を開きます**。1番目の対象をいつも開くことはしません。
- **同じ画面の中で、ちがう期間を並べません**。
- 終わった日の不足のように、もう直せない印は出しません。
- 入口の数と、行き先で同じ範囲を見たときの数は同じにします（12）。範囲がちがうときは「11/02から」のように範囲を見せます。

経緯：2026-11-02（[経緯](history.md#基本-13-入口と行き先)）。

## 15. 設定で使わない機能の表示を消す

使う人や対象（店・チームなど）によって使わない機能があるアプリでは、設定で「やり方」を選べるようにし、使わない機能の表示をアプリの全部のページから消します。

- **出す・出さないはアプリで1か所に決めます**（関数1つ）。画面ごとに条件を書きません。新しい表示を足すときは、まずどのやり方の表示かを決めます。
- **消すのは表示だけで、データは消しません**。オフにした対象でも、何か入っていればその札・行は出します。
- **全部まとめて見る画面では、1つでもそのやり方なら入口を出します**。対象を選んでいる画面はその対象の設定で決めます。
- **消すだけでなく、代わりの仕事に替えます**。その対象が代わりにする仕事を、**その仕事が本来あるページ**に出します。関係のないページに代わりの仕事を出しません。
- ホームのやること・数・通知・使い方の説明も、同じ決まりで出し分けます（8-2・12・14）。

経緯：2026-11-10〜11-12（[経緯](history.md#基本-15-設定で使わない機能の表示を消す)）。
