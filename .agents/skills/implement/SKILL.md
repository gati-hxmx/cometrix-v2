# 実装（implement）

## 手順

1. 最新の main から作業ブランチを作る（Claude は `claude/<Issue番号>-<短い名前>`、Codex は `codex/…`）。
2. 受け入れ条件ごとに、まず失敗するテストを書く。
3. テストが通る最小の実装をする。既存の構成・命名・共通部品に合わせる。
   - 画面を作る・変えるときは、先に [デザインのルール](../../../docs/design/README.md) の関係する章を読む。色は [配色](../../../docs/design/colors.md) の変数だけ、絵は [アイコン](../../../docs/design/icons.md) の線のアイコンだけを使い、共通部品を作り直さない。ルールに合わない指示があれば指示を優先し、同じ PR でルールを書き直す。
   - 画面を作る前に、[オーナーがよく指摘すること](../../../docs/design/README.md#オーナーがよく指摘すること) の18個のうち今回の画面に関係するものを書き出し、作ったあとに1つずつ自分で確かめる（引き算・同じ種類のページとそろえる・長い名前で収まる・重ねて押し出さない、は毎回）。
   - `scripts/check` の「デザインのルールの機械チェック」（`scripts/design-lint`）が止めたものは、例外にせず直す。どうしても要るときは、その行に `design-lint: allow <理由>` と書き、PR にも理由を書く。
4. `scripts/check` を実行し、通るまで直す。
   - テストを消す・スキップする・期待値を実装に合わせて書き換えることはしない。
   - 同じ失敗で3回直せなければ、原因の仮説と試したことを書いて escalate する。
5. こまめにコミットする。コミットメッセージには何をなぜ変えたかを書く。
6. 仕様の変更が必要になったら、勝手に変えずに spec に戻る。
