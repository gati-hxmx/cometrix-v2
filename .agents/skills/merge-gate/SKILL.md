# マージ判定（merge-gate）

[リスク基準](../../../docs/risk-policy.md) の「自動マージの条件」をすべて確かめます。

## 手順

1. 次を1つずつ確かめ、PR にチェックリストとしてコメントする。
   - [ ] CI がすべて緑
   - [ ] 別の AI のレビューで必須の指摘が残っていない
   - [ ] 画面・操作の変更があれば verify で確認済みで、ui-review で必須の指摘がない（「画面は未確認」のままではない）
   - [ ] リスク判定が `risk:low` か `risk:medium`（差分を見て判定し直す。高リスクのファイルが含まれていないか）
   - [ ] PR に仮定・確認結果・残課題が書かれている
2. すべて満たす → `gh pr merge --auto --squash --delete-branch` で自動マージを予約する。
3. リスク判定だけが `risk:high` → escalate（人にマージの承認を頼む）。
4. それ以外の条件を満たさない → 足りないものを担当のスキルに戻す（verify・ui-review・address・ship）。

GitHub のルールで `CODEOWNERS` のファイルには人の承認が必須なので、判定を誤っても高リスクのファイルは自動ではマージされません。

## 次に呼ぶスキル

- マージされた → release
- 高リスク → escalate
