# CI 修正（fix-ci）

## 手順

1. 失敗したジョブのログを読み、どのチェックがなぜ落ちたかを特定する。
2. 手元で同じチェックを実行して再現する。再現できなければ、環境差（バージョン・環境変数・時刻）を疑う。
3. 原因に対する最小の修正をする。修正が失敗の範囲を超えて広がらないようにする。
4. 同じチェックが手元で通ることを確かめてから push する。
5. PR に「失敗の原因・直したこと・確かめたこと」をコメントする。

## してはいけないこと

- テストを消す・スキップする・リトライを足して隠す・期待値を書き換える
- CI の設定を弱める（高リスク）
- 空のコミットで CI をやり直させる

## 回数の上限

同じ PR で fix-ci が3回続けて失敗したら、原因の仮説と試したことをまとめて escalate する。

## 次に呼ぶスキル

- review（修正の内容を別の AI が確かめる。小さな修正なら merge-gate へ）
- 3回失敗 → escalate
