# リリース（release）

実際のデプロイは `.github/workflows/release.yml`（技術スタックを決めたときに stack-select が書く）が行います。AI は本番の認証情報を持たず、ワークフローを見守って判断します。

## 手順

1. マージ後に release ワークフローが始まったことを確かめる。
2. ステージング（またはプレビュー）でスモークテストが通ったことを確かめる。失敗したら本番には出さず、修正 Issue を起こして triage へ。
3. 本番の段階公開（例：5% → 25% → 100%）の各段階で、エラー率・応答時間を監視の結果で確かめる。閾値はスタックごとに `docs/stack.md` に書く。
4. 閾値を超えたら、ワークフローの自動ロールバックが動いたことを確かめ、incident へ。
5. 全段階が終わったら、元の Issue に「本番反映済み」とコメントする。新機能はフィーチャーフラグで段階的に有効にする。

## 次に呼ぶスキル

- 正常 → 終了
- 異常・ロールバック → incident
