# 障害対応（incident）

## 手順

1. 影響を抑える：直前のリリースが原因なら、ロールバック済みか確かめる。済んでいなければ release ワークフローのロールバックを実行する。新機能ならフィーチャーフラグを切る。
2. `scripts/notify` で、何が起きたか・影響範囲・取った対応を通知する。
3. 原因を調べる：エラーログ・直前の差分・監視の推移。個人情報をコピーしない。
4. 修正 Issue を起こす：再現手順、原因の仮説、直し方の案、再発防止のテスト。`incident` と `risk:*` ラベルを付ける。
5. 別の AI（Codex）に原因の見立てを確かめてもらう。
6. 次の場合は escalate する：ロールバックで直らない、データが壊れた・漏れた可能性がある、外部への送信が誤って行われた。

## 次に呼ぶスキル

- triage（修正 Issue）
- 上の escalate 条件 → escalate
