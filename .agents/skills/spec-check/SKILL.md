# 仕様チェック（spec-check）

仕様を書いた側と別の AI が、仕様だけを読んで問題を指摘します。主に Codex が担当します。

## 確かめること

- 受け入れ条件が、テストで確かめられる形になっているか
- 異常系・境界値・権限（誰が何をできないか）が抜けていないか
- 条件同士の矛盾、既存の振る舞いとの食い違い
- 仮定が妥当か。外れたときの影響が大きい仮定はどれか
- リスク判定が [リスク基準](../../../docs/risk-policy.md) と合っているか

## 出し方

- 重要な順に、1件ずつ「問題・理由・直し方の案」を書く。好みの問題は書かない。
- 問題がなければ「指摘なし」と書く。
- Issue にコメントする。

## 次に呼ぶスキル

- spec（仕様を書いた側が反映する）。指摘なしなら plan
